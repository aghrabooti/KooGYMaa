# نسخهبندی و انتشار ZIP پروژه (فارسی)

این سند توضیح میدهد که بعد از **هر تغییر** چگونه یک نسخه ZIP از کل پروژه ساخته
میشود، چرا نام فایل عوض میشود، و چگونه روی لایو سرور در دسترس قرار میگیرد.

## ۱. قانون نامگذاری

| نسخه | نام فایل | دلیل |
| --- | --- | --- |
| `v1` | `KooGYMaa-v1.zip` | نخستین نسخه کامل پروژه |
| `v1.1` | `KooGYMaa-v1.1.zip` | تغییر کوچک بعدی (متن، استایل، اصلاح جزئی) |
| `v1.2` | `KooGYMaa-v1.2.zip` | تغییر کوچک بعد از آن |
| `v1.3` | `KooGYMaa-v1.3.zip` | پوشش کامل حالت شب در همهٔ قابها |
| `v2` | `KooGYMaa-v2.zip` | قابلیت بزرگ یا بازطراحی اساسی |

قاعده ساده: **هر تغییر = یک فایل تازه با شماره جدید**. نسخههای قدیمی حذف
نمیشوند و در بایگانی قابل دانلود باقی میمانند. نسخه `vX.0` بهصورت خلاصه `vX`
نوشته میشود (مثلاً `v2` نه `v2.0`).

- `--bump minor` (پیشفرض): `v1 → v1.1 → v1.2 → …`
- `--bump major`: `v1.2 → v2 → v2.1 → …`
- `--version v3.4`: تعیین دستی شماره نسخه.

## ۲. ساخت نسخه

```bash
npm run release          # تغییر کوچک: نسخه بعدی v1.1
npm run release:minor    # همان
npm run release:major    # تغییر بزرگ: نسخه بعدی v2
npm run release -- --bump minor --note "فارسیسازی صفحه پیامها"
```

اسکریپت `scripts/release.mjs`:

1. شماره نسخه بعدی را از `releases/VERSIONS.json` میخواند.
2. با `zip` یک فایل `releases/KooGYMaa-<نسخه>.zip` از **کل پروژه** میسازد.
3. پوشههای `node_modules`، `.git`، `.next`، خروجیهای بیلد، فایلهای `.env`،
   پایگاهدادههای محلی `*.db`، پشتیبانها و فایلهای ZIP قبلی را حذف میکند
   (فایل `.env.example` بهعنوان الگو دوباره اضافه میشود).
4. اندازه و `SHA-256` فایل را حساب میکند و مانیفست `releases/VERSIONS.json` و
   `releases/CHANGELOG.md` را بهروز میکند.

فایلهای ZIP تولیدشده در `.gitignore` قرار دارند (خروجی هستند، نه سورس)؛
مانیفست و changelog در مخزن نگهداری میشوند. هر کسی مخزن را بگیرد میتواند با
`npm run release` همان نسخهها را بازتولید کند.

## ۳. لایو سرور دانلود

```bash
npm run releases:serve          # پیشفرض: پورت ۴۱۷۳، روی 0.0.0.0
PORT=8080 npm run releases:serve
```

`scripts/release-server.mjs` یک سرور بدون وابستگی خارجی است:

- `/` → صفحه فارسی RTL با فهرست همه نسخهها، آخرین نسخه، تاریخ شمسی، حجم،
  بخشی از امضای SHA-256 و دکمه دانلود.
- `/download/KooGYMaa-v1.zip` → دانلود مستقیم فایل ZIP.
- `/api/versions` → مانیفست JSON برای استفاده برنامهای.
- `/health` → بررسی سلامت سرور.

مانیفست در **هر درخواست** خوانده میشود؛ بنابراین بعد از `npm run release`
نسخه تازه بدون نیاز به راهاندازی دوباره سرور در صفحه ظاهر میشود. سرور به
`0.0.0.0` متصل میشود و هدرهای جلوگیری از iframe ندارد، پس برای پیشنمایش
زنده (Arena / پروکسی) مناسب است.

## ۴. اجرای پیشنمایش آفلاین برنامه (اختیاری)

```bash
npm run db:local
DATABASE_URL=file:./dev.db PREVIEW_MODE=1 npm run dev -- -H 0.0.0.0 -p 3000
```

حسابهای نمونه: `trainer@koogymaa.test` (مربی) و `member@koogymaa.test` (شاگرد)
با گذرواژه `KooGYMaa123!`. متغیر `PREVIEW_MODE=1` فقط برای پیشنمایش داخل
iframe هدرهای `X-Frame-Options` (در `next.config.ts` و `proxy.ts`) و
`frame-ancestors` را نرمتر میکند و `allowedDevOrigins` را باز میگذارد؛ در
پروداکشن همچنان سختگیرانه باقی میمانند.

## ۵. تغییرات نسخه v1

- زبان پیشفرض همه بخشها **فارسی (RTL)** شد؛ انگلیسی همچنان با دکمه `EN | فا`
  در دسترس است.
- متنهای انگلیسی باقیمانده در صفحات عمومی، خطاها، پیشخوان و اعلانها به
  فارسی ترجمه شدند و اعلانهای ارتباطی به صفحه «پیامها» هدایت میشوند.
- بخش **ارتباط مربی و شاگرد** بازطراحی شد: صندوق گفتگوی دونظامواره
  (`/trainer/messages` و `/user/messages`) با جستجو، فیلتر خواندهنشدهها،
  پاسخهای سریع، نشان پیام خواندهنشده، تاریخ شمسی، ارسال با اینتر، حالت
  موبایل و پشتیبانی از تم تاریک.
- اندازه قلمها و دکمههای پنلهای قدیمی برای خوانایی و لمس آسانتر افزایش یافت.
- API امن `/api/messages` و `/api/messages/read` اضافه شد؛ پیامها روی همان
  مدل `Feedback` و با احراز هویت نقش و مالکیت رابطه مربیگری ذخیره میشوند.

## ۶. حالت شب در همهٔ بخشها (v1.3)

`app/dark-mode.css` بعد از `globals.css` و `usability.css` بارگذاری میشود و
تمام سطوح و قابهایی را که رنگ روشن ثابت داشتند (از جمله فرم «طرح تمرینی
تازه»، فرم «طرح تغذیه تازه»، کارتهای طرح، ویرایشگر روزها، وعدهها، جداول،
پنلها، هشدارها و مرکز پیامها) به توکنهای تاریک `--card-bg`،
`--card-bg-raised`، `--field-bg`، `--line-soft` و `--text-soft` وصل میکند.
دکمهٔ تغییر تم در صفحهٔ «انتخاب فضای کاری» هم اضافه شد تا هیچ صفحهای بدون
راه فعالسازی حالت شب نماند.

`tests/dark-mode.test.ts` بهصورت خودکار `globals.css` را میسنجد: اگر سطح یا
قاب روشن تازهای بدون معادل `.theme-dark` اضافه شود، تست شکست میخورد.
